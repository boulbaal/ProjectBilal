# INTAKE

Everything the setup needs from the business. The AI asks for these in groups. Each item says where it goes and why it is needed. Have them at hand before you start.

Secrets go into `.env` (never committed). Business facts go into `knowledge/`.

## Group A: WhatsApp (Meta Cloud API)

| Item | `.env` key | Where to find it | Why |
|---|---|---|---|
| App ID | `META_APP_ID` | developers.facebook.com, your app, App settings, Basic | Identifies your app |
| App secret | `META_APP_SECRET` | same page, "Show" | Verifies that webhooks really come from Meta |
| Permanent access token | `META_ACCESS_TOKEN` | Business settings, System users, generate token with `whatsapp_business_messaging` and `whatsapp_business_management` | Lets the service send messages. Must be a **permanent** system-user token, not the 24-hour test token |
| Phone number ID | `META_PHONE_NUMBER_ID` | WhatsApp, API setup, "Phone number ID" | Which number sends |
| WhatsApp Business Account ID | `META_WABA_ID` | same page | Needed for webhook subscription |
| Webhook verify token | `META_VERIFY_TOKEN` | you invent this, any long random string | Meta sends it back when registering the webhook |

Checks the AI will do: app is in **Live** mode, not Development; the phone number is registered and not in use in the normal WhatsApp app; a test webhook verification succeeds.

## Group B: Mailbox

| Item | `.env` key | Why |
|---|---|---|
| Address the assistant reads and sends from | `MAIL_ADDRESS` | |
| Provider | `MAIL_PROVIDER` | `gmail`, `microsoft`, `imap` (generic). Determines login method |
| IMAP host and port | `MAIL_IMAP_HOST`, `MAIL_IMAP_PORT` | Reading. Default 993 |
| SMTP host and port | `MAIL_SMTP_HOST`, `MAIL_SMTP_PORT` | Sending. Default 587 |
| Password or app password | `MAIL_PASSWORD` | For Gmail and Microsoft this must be an **app password** with 2FA on, not the normal password |
| Poll interval in seconds | `MAIL_POLL_SECONDS` | Default 60. Email has no push without extra setup; 60 seconds is fine for a few dozen mails a day |

Provider notes:
- **Gmail / Google Workspace**: enable 2-step verification, create an app password, IMAP must be enabled in Gmail settings. Host `imap.gmail.com` / `smtp.gmail.com`.
- **Microsoft 365**: app passwords may be disabled by the admin. If so, the AI will tell you and propose OAuth, which takes more setup.
- **Other (Combell, OVH, ...)**: look up "IMAP settings" in your provider's help pages.

## Group D: Server

| Item | `.env` key | Why |
|---|---|---|
| VPS IP or hostname | `VPS_HOST` | Where the service runs |
| SSH user | `VPS_USER` | Usually `root` on a fresh VPS, or a sudo user |
| SSH key path on this computer | `VPS_SSH_KEY` | Passwordless login for deploys. The AI can generate one |
| Public domain | `PUBLIC_DOMAIN` | e.g. `bot.yourcompany.com`. An A record must point to the VPS IP **before** deploy, HTTPS needs it |
| Approval secret | `APPROVAL_SECRET` | random, generated by the AI. Signs the approve/reject links |

Minimum VPS: 1 vCPU, 1 GB RAM, Ubuntu 22.04 or 24.04, ports 80 and 443 open.

## Group E: People and behaviour

| Item | Goes to | Why |
|---|---|---|
| Approver email(s) | `.env` `APPROVER_EMAILS` | Who gets "please check this reply" mails. Comma-separated |
| Business hours and timezone | `knowledge/company.md` | The assistant can say "we reply tomorrow morning" outside hours if you want |
| Languages customers write in | `knowledge/company.md` | Replies in those languages only; others escalate |
| Should the assistant reply at night and weekends | `knowledge/company.md` | Yes/no |
| Dry run | `.env` `DRY_RUN` | Stays `true` until all tests pass |

## Group F: Knowledge (business facts)

Not secrets, but the setup cannot work without them.

| Item | Goes to |
|---|---|
| What the company does, products, service area, address, phone, website | `knowledge/company.md` |
| The 10 to 30 questions customers ask most, with the answer you give | `knowledge/faq.md` |
| Price list and how a quote is calculated (per unit, per m2, options, placement, delivery, minimum order, VAT) | `knowledge/pricing/rules.yaml` via the quote-calculator agent |
| 3 real quotes you made, with the input and the final price | used to verify the rules |
| Mailbox history (read access during training) and WhatsApp chat exports (.txt from the phone, Settings, Export chat) | read by knowledge-trainer, distilled into `knowledge/style.md` and `faq.md`, raw exports are **not** kept in the repo |
| What must always go to a human | `knowledge/escalation.md` |
| What the assistant must never say or promise | `knowledge/escalation.md`, section "Never" |

## What the AI must confirm before moving on

- [ ] `.env` exists, every required key is filled, `.gitignore` contains `.env`
- [ ] Meta webhook verification succeeded against the public domain (or a temporary tunnel in phase 2)
- [ ] IMAP login succeeded and one test mail was read
- [ ] SSH to the VPS succeeded
- [ ] Owner has seen the full list of what was collected (secrets masked) and confirmed it
